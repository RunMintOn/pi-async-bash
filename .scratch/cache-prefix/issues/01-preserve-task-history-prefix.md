# 01: 保持后台任务状态更新时的历史前缀稳定

**What to build:** 后台任务交接、运行和完成时，任务状态快照只补充在请求尾部，不再插入已有历史之前。保留自动完成通知、会话恢复和压缩后的任务状态恢复能力。

**Blocked by:** None (can start immediately).

**Status:** completed

- [x] 真实 provider 请求转换后的历史消息及顺序不因任务状态快照变化而改变；首次交接保留先前完整请求前缀，后续变化最多影响先前的尾部快照及其后的新增内容。
- [x] 任务完成后仍收到正确且不重复的完成通知。
- [x] 会话恢复和压缩后仍能获取当前任务状态，恢复快照保持独立的 16 KiB 总预算。
- [x] 新增回归先在旧实现上失败，再在修复后通过；现有生命周期检查通过。
- [x] 不调用真实模型 API，不修改全局配置或用户正在运行的其他会话。

## 验证记录

- 请求前缀回归在旧实现上失败，修复后通过。真实 provider 适配器使用本地拦截的 fetch，不连接模型服务。
- 完整测试 18/18 通过，包含真实 63 秒交接、完成通知、RPC、fork、reload、会话归属、崩溃恢复、压缩后的状态恢复及 compact 兼容。
- 类型检查及差异空白检查通过；16 KiB 恢复预算与任务筛选逻辑未修改。
- 红灯日志：`/tmp/async-bash-cache-red.log`；完整回归：`/tmp/async-bash-cache-full.log`；类型检查：`/tmp/async-bash-cache-check.log`。
- 未验证真实 provider 的缓存命中率；由用户日常使用观察。尾部临时快照仍可变化，不承诺整个请求前缀始终相同。
