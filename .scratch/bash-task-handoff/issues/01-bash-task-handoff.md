# T11 — 长命令交接、有限等待与原会话自动接续

状态为已实现 · 开发和验收基线为 Pi 1.6.0

## Problem Statement

用户希望在 Pi 里照常运行测试和构建。短命令应当场返回。长命令应当只执行一次，在等待期间允许模型继续其他工作。用户还希望随时检查完整日志，并在命令结束时由原会话主动处理结果。当前实验版使用可交互的进程会话，后续输入和等待共用一个工具，完成后需要调用方主动接续。

## Solution

模型使用 `bash` 启动命令。前台等到 30 秒时，如果命令仍在运行，工具交还控制权并提供任务 ID 和可直接读取的日志路径。模型可以继续工作、查文件，或者调用 `bash_task` 等一段时间并查看日志末尾。完成结果经当前等待调用或原会话通知交付。即使模型已经结束本轮，Pi 也能在结果到达时自动接续。

## User Stories

1. 作为模型，我希望沿用原生 `bash` 的命令和超时参数，以便普通命令按熟悉的方式执行。
2. 作为用户，我希望短测试直接给出最终结果，以便一次调用就能判断成败。
3. 作为用户，我希望长命令交接后由原进程继续执行，以免重复产生副作用。
4. 作为模型，我希望在交接时得到任务 ID，以便稍后等待同一次执行。
5. 作为模型，我希望同时得到完整日志路径，以便立即查阅交接前后的输出。
6. 作为模型，我希望能用 `read`、`tail` 和 `grep` 自选范围，以便从较早的输出定位失败原因。
7. 作为模型，我希望一次调用就能等待并查看近期输出，以便决定下一步。
8. 作为模型，我希望等待时长可以设为零，以便立即取得快照。
9. 作为模型，我希望任务提前退出时等待立即返回，以便及时处理失败。
10. 作为用户，我希望等待到期或取消等待后任务继续运行，以便随后恢复查看。
11. 作为用户，我希望执行超时跨越交接继续生效，以便限制命令的总运行时间。
12. 作为用户，我希望能显式停止已交接的任务，以便清理卡住的命令。
13. 作为模型，我希望能区分正常退出、超时和停止，以便准确说明结局。
14. 作为模型，我希望知道预览是否截断，以便决定是否搜索完整日志。
15. 作为用户，我希望结果能唤醒空闲的原会话，以便无需手动催问。
16. 作为用户，我希望忙碌的会话能在后续请求中接到结果，以免打断正在执行的工具。
17. 作为用户，我希望切换会话后结果仍归属原会话，以免把任务混在一起。
18. 作为模型，我希望已通过等待收到的结果只在主动重查时再次返回，以免重复处理同一次退出。
19. 作为用户，我希望在后续轮次继续访问日志和任务结果，以便复查。
20. 作为用户，我希望 Pi 正常退出时清理受管进程和临时日志，以免长期累积。

## Implementation Decisions

- **模型接口。** 提供 `bash` 和 `bash_task` 两个工具。`bash` 接受必填 `command` 和可选 `timeout`，单位为秒。参数校验、缺省超时、Shell 环境、短命令的输出与错误处理以目标 Pi 原生 Bash 为基准。替换实验版的 `yield_time_ms`、`tty` 和 `write_stdin` 接口。直接调用和 codemode 应得到相同的业务结果，工具描述同步说明交接和自动通知。
- **执行与交接。** 从启动时记录标准输出和标准错误，并从同一时刻计算执行超时。30 秒只决定首次调用何时返回。结束先发生，则按原生短命令路径返回。交接先发生，则只返回 `status: running`、`task_id` 和 `log_path`。任务 ID 引用本次执行的记录，在原进程退出后仍能查询。
- **完整日志。** 每次执行使用独立日志，交接时路径已可读，后台持续追加。`bash_task` 和完成通知都引用同一文件。直接读文件没有消费语义。输出结束时应收齐命令已经写出的尾部，沿用已有管道排空行为。若日志写入失败，应将故障显式交付给调用方；残缺文件不得标记为完整。
- **有限等待。** `bash_task` 接受必填 `task_id` 和可选的 `wait_seconds`，范围 0–300 秒，默认 30 秒。零秒立即查看。运行中遇到新输出继续等待，直到命令结束或本次等待到期。终态可立即重查。每次返回任务状态、`log_path`、`output_tail` 和 `truncated`。正常退出保留实际退出码，包括非零退出码。执行超时和显式停止分别给出可区分的终止原因。
- **预览。** 以当次返回时已经写出的日志为准，最多取末尾 40 行且最多 4 KiB，字节数按 UTF-8 计算。优先保留完整行，未换行的末段也算一行。`start_line` 和 `end_line` 是完整日志内从 1 起算的行号。若最后一行单独超限，保留字符边界完整的后缀并标记 `partial_line`。因任一上限省略前缀时 `truncated` 为真。空日志返回空字符串及完整日志路径，省略行号。重复查询可以得到相同预览。
- **结果交付。** 前台完成由 `bash` 交付。交接后完成时，若模型直接调用 `bash_task` 并收到终态，省去自动通知。codemode 内部的等待只把结果交给脚本，仍保留自动通知。一次等待返回 `running` 或被取消后，最终交付仍然待办。完成消息已经送出后，主动重查从日志和终态记录生成预览。
- **会话接续。** 空闲的原会话收到完成消息时自动开启一轮。正在工作的原会话在下一次模型调用时取得消息。切到其他会话期间为原会话保留结果，回到原会话时接续。同一次完成只触发一次自动交付。
- **缓存前缀。** 工具描述和系统提示保持固定，任务状态保存在进程内。完成通知只追加到原会话末尾。用同一会话中 OpenAI 适配器发出的序列化请求检查整个已有消息前缀和工具定义。空闲唤醒和忙碌投递都必须通过。
- **取消和清理。** 交接前取消 `bash`，停止命令和受管子进程。交接后取消 `bash_task`，只取消本次等待。沿用用户停止命令 `/bash-stop`，以任务 ID 指定对象。任务结果和日志在所属 Pi 进程存续期间跨轮次、切换会话保留。Pi 正常退出时终止受管进程并清理本进程创建的临时日志。工具查询和停止校验任务归属。

## Testing Decisions

- 以现有 Pi RPC 测试为主要验收入口，使用确定性的模型响应驱动真实命令，观察工具返回、实际日志文件、原会话消息及唤醒轮次。断言对外可见的行为。
- **主动等待。** 测试命令先打印标记，运行超过 30 秒后向标准错误写入未换行的失败原因并以非零码退出。验证交接返回时文件已包含标记，等待提前返回，退出码、末尾预览和文件内容一致，原会话没有重复通知。
- **取消等待。** 重跑同一旅程，取消等待并结束模型轮次。验证进程继续，退出后原会话自动开启一轮并取得完整结果。再覆盖模型仍忙和切换会话两种投递时机。
- 复用已有工具调用与生命周期测试入口验证短命令、零秒快照、等待到期、执行超时、前台取消、用户停止、任务归属和正常退出清理。保留原生 Bash 对照检查。交接边界和等待边界分别驱动两种事件顺序，验收一次最终交付。
- 通过任务结果入口验证空日志、超 40 个短行、单个超长中文行、无末尾换行、恰好达到上限及完整日志可回查。日志写入失败时检查面向调用方的故障结果。

## Out of Scope

持续写入 stdin、PTY 终端交互、回答运行中提示、模型可调的预览行数、增量日志游标、跨 Pi 进程恢复任务，以及异常退出后的临时文件回收。

## Further Notes

40 行和 4 KiB 是固定预览上限。完整日志占用随输出量增长。首次交接阈值和等待默认值恰好同为 30 秒，前者从命令启动计时，后者从每次 `bash_task` 调用计时。`wait_seconds` 的有效范围为 0–300 秒。Fork 继承历史消息，任务的查询、停止和通知仍归原会话。

## 维护要点

- **缓存与接续。** 历史实现把变化的任务快照放在历史消息之前，导致后续请求改写已有缓存前缀。见 [旧修复](../../cache-prefix/issues/01-preserve-task-history-prefix.md) 和 `a524c24`。T11 借鉴 [OpenCode 的追加消息](../../async-bash-research/opencode.md)，让后台状态留在进程内和 TUI。改投递时保留 `index.ts` 的分工：空闲时用 `sendMessage` 唤醒，忙碌时在 `turn_end` / `agent_before_settle` 追加消息。Unreal Agent 的占位结果替换会修改已发历史。执行 `test/cache-prefix.test.mjs`，比较 OpenAI 适配器序列化后的全部已有消息（含系统提示）和工具定义。通过只代表客户端保持了前缀，服务端命中率未测。
- **结果可见性。** 在 `turn_end` 根据顶层 `bash_task` 的工具结果确认模型已收到终态。codemode 内部取得终态只保证脚本拿到了值，脚本可以丢弃它。保留原会话通知，脚本同时输出终态时允许重复。`test/rpc.test.mjs` 覆盖直接等待去重、脚本丢弃终态、取消等待和切回原会话。任务按原会话 ID 归属，历史引用本身不转移控制权。
- **日志与时长。** 复用 Pi 公开的 `createBashToolDefinition` / `createLocalBashOperations`，由底层返回实际退出码并保留原生管道排空行为。同步逐块落盘会占用事件循环，因此用异步流并在结束写入后发布终态。当前原生 `onData` 回调没有背压接口，慢盘下写入队列仍可能增长。高吞吐 TUI 流畅度未实测。完整日志保留到正常退出，终态只缓存元数据。提前淘汰日志会改变回查契约。固定尾部预览加行号支持按需查早期输出。模型等待窗口参考 Codex 的 300 秒上限，交接阈值的样本与限制见 [THRESHOLD_ANALYSIS.md](../../../THRESHOLD_ANALYSIS.md)。
- **提示词。** `description` 放执行契约和参数语义，`promptSnippet` 放一行工具选择提示，`promptGuidelines` 写行动和原因。Pi 把 guidelines 平铺在规则区，每条写清工具名。参考 [调研对照](../../async-bash-research/comparison.md)：Codex 说明等待范围，Amp 区分等待与接续，OpenCode 和 Unreal Agent 给出交接后的下一步。用 `test/instructions.test.mjs` 检查 direct 和 codemode-only 的真实请求。用户要求模型理解理由，例如重复启动会重复副作用，原会话会被唤醒所以可以结束本轮。
