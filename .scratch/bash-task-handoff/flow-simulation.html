模型实际看到的提示词

这套工具对模型暴露四类文本。系统提示词里的清单和规则、请求体里的工具定义，以及交接和完成时送回的文本。每段英文下面是对应的中文。

① 系统提示词 · 工具清单system prompt → section: tools

- bash: Run Bash commands with background handoff for long-running commands - bash_task: Inspect a handed-off Bash task or wait on it

每个工具一行。没有 snippet 的工具根本不会出现在这个清单里，所以 snippet 写不好，模型可能压根不知道有这个工具。

第一行，运行 Bash 命令，长命令会交接到后台。
第二行，查看或等待已交接的 Bash 任务。

② 系统提示词 · 规则system prompt → section: rules

- You can inspect PI_* environment variables for current model and session details.

来自原生 bash，保留了。你可以查看 PI_* 环境变量，获取当前模型和会话的信息。

- When bash hands off a command, running means the original command is still executing. Pi tracks it and automatically delivers the final result to this conversation. Continue work that can proceed without it. If all remaining work depends on the result, end your turn; Pi will resume the conversation when the result is ready. Do not rerun the command just to get its result, since that can repeat its side effects.

bash 交接后，running 表示原命令仍在执行。Pi 会跟踪它，把最终结果自动送回本会话。继续做能独立推进的工作。如果剩余工作都依赖结果，就结束本轮。结果就绪时 Pi 会接续本会话。仅为取得结果而重跑可能重复命令的副作用。

- Do not poll handed-off Bash tasks for completion by sleeping, repeatedly reading logs, or repeatedly calling bash_task. Pi already tracks completion. A sleep call can keep you waiting even after the command has finished.

为确认已交接任务是否结束，无需调用 sleep、反复读日志或反复调用 bash_task。Pi 已经在跟踪完成状态。sleep 可能让你在命令结束后还要继续等。

- Use bash_task with wait_seconds: 0 if output already produced can inform an action now, or if the user asks for progress. If the user explicitly asks to block on an existing task, make one bounded bash_task call with an explicit wait_seconds. If it returns running, leave completion to Pi.

已有输出能帮助决定眼下的动作，或用户询问进度时，用 bash_task 并传 wait_seconds: 0。用户明确要求阻塞等待已有任务时，调用一次 bash_task，并明确填写等多久。若仍在运行，等 Pi 自动送达结果。

③ 工具定义 · bash请求体 tools[].description + parameters

Run a Bash command in the current working directory. If it finishes before handoff, return its stdout and stderr. The text result keeps at most the last 2,000 lines or 50 KiB, whichever limit is reached first. If truncated, the full output is saved to a temporary file. If the command is still running after 30 seconds, hand it off and return status: running, task_id, and log_path. The same command keeps running, and Pi delivers its final result to the original conversation automatically.

在当前工作目录运行 Bash 命令。交接前完成时返回 stdout 和 stderr。文本结果至多保留最后 2,000 行或 50 KiB，以先触及的上限为准。若发生截断，完整输出存在临时文件里。命令过了 30 秒还在运行时，交接并返回 status: running、task_id 和 log_path。原命令继续运行，Pi 会把最终结果自动送回原会话。

必填command: string — Shell command to execute.

要执行的 shell 命令。

可选timeout: number — Maximum command runtime in seconds, including after handoff. Reaching this limit terminates the command. Omit for no timeout.

命令总运行时限，单位为秒，包含交接后的时间。达到时限会终止命令。省略表示不设时限。

④ 工具定义 · bash_task请求体 tools[].description + parameters

Inspect or wait on the handed-off Bash task identified by task_id. Returns its status, exit code when available, log path, and a preview of up to 40 lines and 4 KiB with original line numbers. An already finished task returns immediately. Reaching the wait limit or cancelling the wait leaves the command running. If this call delivers the final result directly to the model, Pi skips the separate completion message.

按 task_id 查看或等待已交接的 Bash 任务。返回状态、可用时的退出码、日志路径，以及带原始行号的预览，上限为 40 行和 4 KiB。已结束的任务立即返回。达到等待上限或取消等待时，命令继续运行。如果这次调用已把最终结果直接交给模型，Pi 会省去单独的完成消息。

必填task_id: string — Task ID returned by bash at handoff.

bash 交接时返回的任务编号。

可选wait_seconds: number — Maximum time this call waits for the task to finish, in seconds. Use 0 for an immediate snapshot. Accepts 0 to 300. Defaults to 30.

最长等待秒数，0 到 300，默认 30。传 0 表示立刻看一眼，不等。

⑤ 交接回执与完成通知tool result · custom message

Bash task <task_id> is still running. Log: <log_path> Pi will deliver the final result to this conversation automatically. Continue independent work, or end your turn to wait.

交接时，回执给出运行状态和日志路径。Pi 会把最终结果自动送回本会话。可以继续独立工作，或结束本轮等待。

Bash task <task_id>: exited with code 1. Log: <log_path> Showing lines 1184–1223 (preview truncated) <最后 40 行或 4 KiB 原始输出>

第一行是状态，退出码非零就写实际的数字，超时写 timed out，被停写 stopped。第二行是完整日志路径。第三行只在有预览时出现，括号里表示前面还有内容没给。最后是该任务的输出尾部。

这段文本和 bash_task 成功返回时用的是同一个格式化函数，所以模型看到的形态一致。

不计入提示词的部分模型看不到

label（bash task）只用于 TUI 显示。outputSchema 不进提示词文本，它是给 provider 做结构化输出约束用的。/bash-stop 是用户斜杠命令，模型没有这个工具。

页面上面那段对话里的时间、task_id 和日志路径都是示例值。

短命令在 30 秒内结束，走原生路径返回，日志立刻删除，不产生 task_id。超过 30 秒才产生任务。

命令是否结束和日志读到哪，是两件独立的事。预览每次都是日志末尾，重复看会看到相同内容，因为日志没有被「消费」这个概念。

完成通知以 custom message 形式出现，位置在历史末尾，前面的消息、系统提示和工具定义都不变，这是缓存前缀能稳住的原因。

页面里的 task_id、时间、日志路径都是示例值，用于说明交互顺序。
